# Kiro usage log

| Date | Kiro feature | What we used it for | Why it helped / friction found |

| 2026-11-05 | Steering (manual) | `#next-task` and `#close-task` as slash commands for the task cycle | Same cycle every time, no rules pasted by hand |
| 2026-11-05 | Custom agent | `reviewer`: read-only reviewer restricted to git diff/log/show | Isolated context, so it reviews the code without the history of how it was written |

| 2026-11-06 | Steering (always) | `testing.md` updated with the user-Kiro exception to the real-service test rule | Keeps the rule and the documented exception in sync, instead of the agent hitting a rule it cannot satisfy |
| 2026-11-11 | Specs | `project-skeleton` (PR #4): npm workspaces, TypeScript, ESLint, Prettier, Vitest, fast-check and the `npm run check` script. Placeholder packages let lint, build and test run before any real feature existed. A single fast-check property test was added to prove the stack works |

On 11 Nov the requirements changed approach before any code was written: the spec picks 3 to 5 key files of a public GitHub repository instead of a hook that marks every file the agent writes | The change was made in the requirements, before any code existed. Why the change of approach helped: to confirm with Luis Miguel |
| 2026-11-11 | Property-based tests | The 9 correctness properties of the `ghost-detection` design, each with a fast-check test: (1) URL round trip, (2) eligible set independent of order, (3) picking is deterministic and bounded, (4) score is an integer from 0 to 100, (5) measuring is deterministic, (6) a branching line never lowers the score, (7) line endings do not matter, (8) report order independent of download order, (9) report JSON round trip | The git history does not show that any of the 9 caught a real bug. The one bug fix in this spec (`811bcd0`, body read failures mapped to `NETWORK_ERROR`) was covered by unit tests added in the same commit. Whether the properties helped in other ways: to confirm with Luis Miguel |
| 2026-11-11 | Hooks | `.kiro/hooks/test-after-task.json` (PR #5): two `PostTaskExec` hooks, a command hook that runs `npm run check` and an agent hook that runs it and fixes failures | Real test in task 2.1 of `ghost-detection`: the trigger fires when a task is marked as completed, not on Start task. Editing `tasks.md` by hand did not fire it. Friction: the Kiro docs do not say whether the output of a `PostTaskExec` command hook reaches the agent, which is why the second (agent) hook exists. Which of the two hooks to keep is still open (see `PLAN.md`) |
| 2026-11-11 | Hooks | `timeout` for the command hook | Friction: `timeout` inside `action` gave a format error. It is a field of the hook itself (`hooks[].timeout`, in seconds, command actions only), next to `trigger` and `action`. Logged in `docs/frictions.md` |
